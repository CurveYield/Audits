# Package Limitations and Audit Follow-ups v1

1. **sdYB helper exact binding remains open.** The live strategy constructor identifies five helper addresses. Each has deployed code, but those helper addresses were unverified on Ethereum Blockscout at package-build time. Their candidate V17 source files are present in the verified sdYB source bundle, but the package does not claim byte-for-byte helper address/source proof.
2. **Fraxtal live explorer connector boundary.** The available Blockscout blockchain connector did not support Fraxtal chain ID 252 in this session. Standard Fraxtal source is instead grounded in the project's prior creation-bytecode verification record, which records exact matches for BoostHub, sdFXS staking, vault, strategy, and converter.
3. **sdCRV converter discrepancy is intentional evidence, not normalized away.** The current frontend inventory lists `0xf4b3…351B`; the replacement-v3 deployment instructions mark that converter as broken, while the current deployed strategy constructor selects `0x78ff…5e82`. Both are retained for audit review.
4. **Yield Lens source has no established live target address in the supplied current inventory.** It remains in the sdYB source bundle because it is part of the release/source tree, but no deployment address is asserted here.
5. **No compile/build proof was generated during packaging.** This is deliberate. The audit workflow may independently compile or reproduce runtime bytecode under its own evidence rules; the package builder did not compile or install dependencies.
6. **External dependencies are not reclassified as CurveYield source.** Their addresses are listed separately for integration analysis.

7. **Newer explorer-verified source is release-correlated, not package-cryptographically rebound here.** The current sdCRV vault/strategy/fixed converter and current sdYB vault/strategy expose verified explorer source with the observed contract names/compiler settings/source family. This package preserves the corresponding original release files, but the packaging pass did not compile or independently derive an explorer source digest. The v6 audit should reproduce exact source/runtime binding as an admission/evidence step.
